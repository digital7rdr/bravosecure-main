## 1b. Wave 2 self-review — what the audit of the fix found, and what was fixed

Wave 2's implementation was audited by **5 independent reviewers per item** (spec-conformance,
correctness, regression, arch-security, test-adequacy) = 15 reviews producing **32 raw findings**.
Each was then put to a **3-verifier adversarial refutation panel**; a finding survived only if
**≥2 of 3 verifiers failed to refute it**. **17 survived. Zero P0, zero P1** — the wave-2 code was
structurally sound; everything below is a P2/P3 sharpening.

### What this review pass tells you

Three things worth noting, because they are the reason the pass was worth running:

1. **Two P2s in RT-2 would have silently defeated the item's own purpose.** The un-park being
   unreachable on network regain means the outbox reliability work would have looked correct in
   tests and still stalled on a real reconnect. That is precisely the class of bug that survives
   code review and dies only on device.
2. **Both fix agents refused a suggested remedy and were right to.** GW-2's literal fix would have
   re-opened SRV-02; CALL-D's would have violated an explicit two-place prohibition in its own
   spec. A verified finding is not a mandate to implement a bad fix.
3. **Half the test-adequacy findings were "this test would pass against the pre-fix code."** Mirror
   tests that re-implement the logic under test prove nothing. Worth watching for in waves 3–8.
