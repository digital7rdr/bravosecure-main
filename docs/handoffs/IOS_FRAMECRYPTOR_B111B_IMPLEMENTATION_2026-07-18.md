# B-111-B — FrameCryptor on iOS, A-to-Z implementation plan (make iOS group calls work like Android)

**Date:** 2026-07-18 · **Status:** PLAN → implementation follows in this repo (Windows authors ALL code; the Mac QA member pulls, compiles, and device-verifies — no code authoring left for the Mac).
**Companion docs:** `docs/handoffs/IOS_GROUPCALL_AND_MESSENGER_PARITY_B111_B117_2026-07-18.md` (§B-111), `docs/ARCHITECTURE_AMENDMENT_SFRAME.md` (the SFrame design this implements), `docs/handoffs/IOS_QA_HANDOFF_2026-07-18.md` (device-QA logistics).

---

## 0. What this is and is not

iOS group calls fail 100% at the S6 gate because iOS has no FrameCryptor: the SFU terminates DTLS-SRTP, so without frame-level AES-256-GCM the server would see plaintext media — the app correctly refuses. This plan **implements the SAME documented SFrame design on iOS** (`ARCHITECTURE_AMENDMENT_SFRAME.md`): identical salt, identical AES-GCM algorithm, identical key-provider parameters, identical JS driver. **No security behavior is invented or changed; the S6 refusal stays byte-identical and only opens when the native probe genuinely passes.** That is why this does not cross the CLAUDE.md stop-condition: it is a second-platform implementation of an already-approved design.

## 1. The stack decision (the make-or-break choice) — VERIFIED

**Problem:** react-native-webrtc's stock iOS framework (JitsiWebRTC 124.x) exposes NO FrameCryptor, and no Swift twin of `BravoFrameCryptorModule.kt` can exist without one. FrameCryptor is a LiveKit-authored libwebrtc extension; on Android we get it from `io.getstream:stream-webrtc-android` via the gradle swap in `patches/react-native-webrtc+124.0.7.patch`.

**Options weighed:**

- **(A) CHOSEN — npm-alias `react-native-webrtc` to `@livekit/react-native-webrtc`.** LiveKit maintains a fork of the exact package we use, built against their `LiveKitWebRTC` xcframework — the framework that HAS FrameCryptor (ObjC classes `LKRTCFrameCryptor`, `LKRTCFrameCryptorKeyProvider`, `LKRTCFrameCryptorFactory`; all RTC symbols are LK-prefixed in their build). Their own React-Native SDK runs E2EE through it in production. The alias form `"react-native-webrtc": "npm:@livekit/react-native-webrtc@<ver>"` keeps the node_modules FOLDER name, so every `import ... from 'react-native-webrtc'`, autolinking, `@config-plugins/react-native-webrtc`, and our patch-package path continue to work untouched.
- (B) iOS-only package divergence (two webrtc packages by platform) — fights Metro + autolinking; rejected.
- (C) Patch stock react-native-webrtc's podspec onto some RTC-prefixed FrameCryptor framework — no maintained candidate verified (Stream's iOS build is SPM-era 114.x, FrameCryptor unconfirmed; LiveKit's is LK-prefixed and needs the fork's renamed ObjC sources anyway); rejected as primary, kept as fallback investigation only.

**Android stays bit-identical under (A):** the fork's `android/` Java is the same upstream tree; we REGENERATE our existing patch against it so Android keeps consuming `io.getstream:stream-webrtc-android` (the exact aar running on devices today) + the same `getRtpSenderById`/`getRtpReceiverById`/`getPeerConnectionFactory` accessors. Net Android diff: none at runtime. This is proven locally on the BlueStacks pair BEFORE push (step §6.1).

**Version pin:** the fork tracks upstream releases — pin the fork version matching the 124.x line we're on (e.g. `@livekit/react-native-webrtc@124.x`, exact version chosen at implementation time from the fork's release list; record it in package.json and below in §8).

## 3. The Swift module — method-for-method contract (source of truth = the Kotlin module)

Mirror `BravoFrameCryptorModule.kt` EXACTLY; JS must need zero platform branches. All names, argument orders, resolve/reject codes identical:

| Method                                                                      | Kotlin behavior to replicate                                                                                                                                              | iOS (LKRTC) mapping                                                                                                                                                                                                                                                    |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `isAvailable()` (SYNC)                                                      | Class.forName probe of the three FrameCryptor classes                                                                                                                     | `NSClassFromString` probe of `LKRTCFrameCryptor` / `LKRTCFrameCryptorKeyProvider` / `LKRTCFrameCryptorFactory` (plus compile-time import)                                                                                                                              |
| `createKeyProvider(ratchetWindowSize, failureTolerance, keyRingSize)` → id  | salt = UTF-8 `"bravo-sframe-v1"`, sharedKey=false, uncryptedMagicBytes=empty, discardFrameWhenCryptorNotReady=true; UUID id into a registry                               | `LKRTCFrameCryptorKeyProvider(ratchetSalt:ratchetWindowSize:sharedKeyMode:uncryptedMagicBytes:failureTolerance:keyRingSize:discardFrameWhenCryptorNotReady:)` — **every argument identical**; registry = dictionary behind a serial queue (the ConcurrentHashMap twin) |
| `setKey(kpId, participantId, index, keyBase64)` → Bool                      | base64 decode, HARD 32-byte check (`KP_BAD_KEY`), `kp.setKey`                                                                                                             | same checks, same reject codes, `setKey(participantId:index:key:)`                                                                                                                                                                                                     |
| `ratchetKey(kpId, participantId, index)` → String?                          | returns next key base64 or null                                                                                                                                           | `ratchetKey(participantId:index:)` → base64 or nil                                                                                                                                                                                                                     |
| `attachSenderCryptor(kpId, peerConnectionId, senderId, participantId)` → id | resolve RtpSender via patched accessor + factory; `createFrameCryptorForRtpSender(factory, sender, participantId, AES_GCM, kp)`; **`setEnabled(false)` before returning** | resolve `LKRTCRtpSender` from the fork's WebRTCModule pc map (§4); `LKRTCFrameCryptor(factory:rtpSender:participantId:algorithm:.aesGcm keyProvider:)`; `enabled = false` before returning                                                                             |
| `attachReceiverCryptor(…)`                                                  | receiver twin                                                                                                                                                             | receiver twin                                                                                                                                                                                                                                                          |
| `setCryptorEnabled(cryptorId, enabled)`                                     |                                                                                                                                                                           | `cryptor.enabled = enabled`                                                                                                                                                                                                                                            |
| `setCryptorKeyIndex(cryptorId, index)`                                      |                                                                                                                                                                           | `cryptor.keyIndex = index`                                                                                                                                                                                                                                             |
| `disposeCryptor(cryptorId)`                                                 | remove+dispose, resolve null even if missing (idempotent)                                                                                                                 | identical idempotence                                                                                                                                                                                                                                                  |
| `disposeKeyProvider(kpId)`                                                  | ditto                                                                                                                                                                     | ditto                                                                                                                                                                                                                                                                  |

Reject codes to keep verbatim: `KP_CREATE_FAILED, KP_NOT_FOUND, KP_BAD_KEY, KP_SET_FAILED, KP_RATCHET_FAILED, WEBRTC_MODULE_MISSING, SENDER_NOT_FOUND, RECEIVER_NOT_FOUND, FACTORY_MISSING, CRYPTOR_ATTACH_FAILED, CRYPTOR_NOT_FOUND, CRYPTOR_SET_ENABLED_FAILED, CRYPTOR_SET_KEY_INDEX_FAILED, CRYPTOR_DISPOSE_FAILED, KP_DISPOSE_FAILED`.

**Byte-for-byte interop invariants (the "connects but can't decrypt" guards):** same salt bytes, same AES-GCM algorithm enum, same key sizes (32), same ratchet window/failure tolerance/key-ring numbers (they live ONLY in `frameCryptorTransport.ts` and flow to both platforms), same participantId strings (JS supplies them — platform-agnostic already), cryptors start disabled until JS pushes the epoch key. FrameCryptor's wire format is symmetric inside libwebrtc builds derived from the LiveKit patch set — stream-webrtc-android (Android) and LiveKitWebRTC (iOS) are both that lineage; the cross-platform decrypt matrix (§7) is the empirical proof gate.

## 4. Reaching the RtpSender/Receiver + factory on iOS

4.1 JS already hands us `peerConnectionId` (`_pcId` — set by the JS layer for BOTH platforms, so `getPeerConnectionNumericId` works unchanged) and the sender/receiver `id` string.
4.2 The fork's iOS `WebRTCModule` keeps the peerConnection map + `peerConnectionFactory`. The Swift module obtains the module instance via the bridge (`bridge.module(for:)` / `moduleRegistry`), then: pc = map[pcId]; sender = `pc.senders.first {{ $0.senderId == senderId }}`; receiver likewise from `pc.receivers`.
4.3 **If** those members aren't visible in the fork's public headers, add a minimal iOS patch hunk to file #2: a `WebRTCModule (BravoAccessors)` category exposing `- (LKRTCPeerConnection *)bravo_peerConnectionForId:(NSNumber *)pcId;` and `- (LKRTCPeerConnectionFactory *)bravo_factory;` — the exact iOS mirror of the Android accessor patch. (Decision recorded at implementation time in §8.)

## 5. What CANNOT be done on Windows (the Mac QA member's list — compile only, no authoring)

1. `npm install` (fetches the fork via the alias; patch-package applies the regenerated patch — watch its output).
2. `npx expo prebuild -p ios --clean` (plugins re-apply everything: build fixes, VoIP, FrameCryptor files).
3. `cd ios && pod install` — **expected turbulence**: the fork's podspec pulls `LiveKitWebRTC` instead of `JitsiWebRTC`. Re-check each patch in `patches/` that touches iOS (`op-sqlite`, `quick-crypto`, `react-native+0.81.5`, `expo-constants`, `argon2`, `stripe`) still applies/compiles — the §1 warning from the founder's own analysis stands: the pod swap replaces the media stack for ALL calls and may break the just-stabilised build; budget a day for pod/header fallout.
4. Xcode build → the §6/§7 gates.

## 8. Implementation log (filled as the work lands below this line)

- **Pinned fork version:** `@livekit/react-native-webrtc@125.0.12` (no 124.x exists in the fork; 125 = same-generation M125 line).
- **iOS symbol correction:** the fork's cocoapods dependency is `WebRTC-SDK =125.6422.07` with module name `WebRTC` and **standard UN-prefixed `RTC*` classes** (the LKRTC prefixing exists only in LiveKit's SPM xcframework). The Swift module uses `import WebRTC` + `RTCFrameCryptor*`. §1's LKRTC note is superseded accordingly.
- **iOS accessor route:** the fork's `WebRTCModule.h` PUBLICLY exposes `peerConnectionFactory` + `peerConnections` — §4.3's fallback patch is unnecessary; the Swift module reads them via KVC (header-independent).
- **Android aar decision CHANGED from §1 (with reason):** the fork's Java ships its own FrameCryptor JS glue (`RTCFrameCryptor.java`) that references `FrameCryptorAlgorithm.AES_CBC`, which Stream's 1.3.10 aar does not export, and the fork already contains `getReceiver` (the ported hunk collided — build proved both). Keeping Stream's aar would mean patching the fork's own glue: MORE surface, more fragility. Android therefore uses the fork's default **`io.github.webrtc-sdk:android:125.6422.04`** — note stream-webrtc-android is itself a webrtc-sdk derivative, so this is the direct lineage of today's stack, and it version-matches the iOS framework (both 125.6422.x → strongest FrameCryptor interop). Consequence: the §6.1 gate is now a REAL regression gate (media stack moves M124-Stream → M125-webrtc-sdk), not just bit-identity confirmation — its emulator call rows are mandatory before push, and the full Android device matrix should be re-run at next QA.
- **Final patch shape:** `patches/react-native-webrtc+125.0.12.patch` = ONE file (WebRTCModule.java), the three Bravo accessors only (fork's package-private getSender/getReceiver reached from the same package).
- **Windows/OneDrive gotcha for future sessions:** node_modules dirs get handle-locked by OneDrive; `rd /s /q` + settle-retries, or extract the npm tarball INTO the locked dir (`npm pack` + `cp`) when rename-based installs EBUSY.
- Commits: `a00640b` (plan), `6258401` (implementation — carried a broken first patch), `<this commit>` (corrected minimal patch + aar decision), `6489fa4` (Mac runbook).

## 9. Rollback

Single-line revert of the package.json alias + restore the previous patch file (git). Android reverts to today's stack verbatim; iOS reverts to "group calls unavailable" (B-111-A behavior). No data/schema/protocol migrations anywhere in this plan.
